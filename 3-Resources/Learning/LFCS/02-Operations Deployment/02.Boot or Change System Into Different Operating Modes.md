## Linux Boot Process
The linux boot process takes these following steps:
- Power on: Starting the computer by pressing the power buttun.
- BIOS/UEFI: Are pieces of software that checks the hardware (POST), and loads the boot loader.
	- BIOS Basic Input/Output System: old system, uses MBR(Master Boot Record) which limits the disk size at 2TB, and uses the first chunk of the hard drive to look for the boot loader.
	- UEFI Unified Etensible Firmware Interface: faster and more secure and more advanced, uses the GUID partition table, and EFI, which is a small partition that has the data to boot the system.
- Loading boot loader to memory, which in turn loads the Operating System's kernel, and the necessary drivers and modules.
- Init system (systemd, systemv, upstart) is then started by the kernel, which is the parent of all the other processes, and is responsible for checking mounted volumes, and determining the target system it should boot to, using target configuration files.
### System Target or Unit File (Boot Mode)
It refers to the state or mode the operating system is configured to run on, it is like the old SysV's runlevels. it is loaded using target configuration files.
- Target files: (man systemd.taget), it is a configuration file that ends in .target extension, encodes information about a target unit of systemd. Target units are used to group units and to set synchronization points for ordering dependencies with other unit files.
	- Where is it located: 
		- Best practice for Systemd unit files: `/etc/systemd/system`
		- Best practice for user unit files: /etc/systemd/user or $HOME/.config/systemd/user. [1](https://unix.stackexchange.com/questions/224992/where-do-i-put-my-systemd-unit-file)

#### Commonly Used System Targets
Table shows most common Systemd targets


| Target     | SysV Runlever | Purpose                                                                                                                    |
| ---------- | ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| rescue     | 1             | Single user mode, with most basic services running, and a rescue shell                                                     |
| multi-user | 3             | CLI only, with all services running.                                                                                       |
| graphical  | 5             | Full multi-user with network and display manager                                                                           |
| emergency  | S             | Single user mode, no services, no mounted file systems, and an emergency shell, this is the most basic level of operation. |
- To show the currently used target in a system:
```
sudo systemctl get-default
```

> [!NOTE] Root user
> Root user must be available on the system to be able to use these targets.

#### Changing Default Boot Target
- Grub
1. open Grub config file located at: `/etc/default/grub`
2. locate the line that reads `GRUB_DEFAULT=0`
3. Change the number to that matches the target, and save.
4. Update the Grub config file with the command: `sudo update-grub`

- Systemd
1. `sudo systemctl set-default multi-user.target`
#### Change System Target on running system.
``` bash
sudo systemctl isolate multi-user.target
```
