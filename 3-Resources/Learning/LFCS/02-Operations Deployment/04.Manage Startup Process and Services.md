### Systemd units
A systemd unit is anything that systemd manages

	service
	socket
	device
	timer

#### Manage systemd services
- Show a service unit file content
```bash
sudo systemctl cat ssh.service
```
- Edit a service unit file
```bash
sudo systemctl edit --full ssh.service
```
- Reset a service unit file to default
```bash
sudo systemctl revert ssh.service
```
- Show the status of a service
```bash
sudo systemctl status ssh.service
```
	- enabled= the service will start at boot.
	- disabled= the service will not start at boot.
	- inactive (dead)= the service is not running
	- active (running)= the service is running
	- Main PID= Process IDentification number of the parent process.
- Start, restart and Stop a service
```bash
sudo systemctl start ssh.service
sudo systemctl restart ssh.service
sudo systemctl stop ssh.service
```
- Reload a service configuration
```bash
sudo systemctl reload ssh.service
```

> #sidenote: the ==reload== tells the services to reload their configuration, it will not reload the service unit file, it is used to when altering the configuration of a service and then reloading it for the configuration to take effect. and without restarting ir (closing and reopening).
> Not All units supports it.

- Reload a service unit file
```bash
sudo systemctl reload-daemon ssh.service
```
> Reload the systemd manager configuration. This will rerun all generators (see systemd.generator(7))

- If reload is not supported
```bash
sudo systemctl reload-or-restart ssh.service
```
- Enable or Disable a unit to start at boot
```bash
sudo systemctl enable ssh.service
sudo systemctl disable ssh.service
```

##### Miscellaneous commands
	- is-enabled: checks if the service is enabled
	- --now: enables and starts at the same time.
	- mask: will link the unit files to /dev/null, to make it impossible to start.
	- unmask: reverts the effects of mask.
	- list-units: lists available units on the system.
		- (--type service --all): lists services only.
