# Version Control System
 Are systems used to track file changes, and account those changes, it is usually used in Software Development projects, to make collaboration between multiple developers or teams easy.
## Git 
 Git is a distributed version control system that allows a large set of people to work on the same project, it has repositories, that store the data and the information about its change, a developer usually have two repos, local and remote:
 Local repo: it is used by the developer in his/her machine, to modify the data and test it without touching the remote repo.
 Remote repo: Used and shared by the entire team.
### Tips and Tricks
- Set username and email
```
git config --global user.name "username"
```

```
git config --global user.email "user@email.com"
```

This command makes the username and email as global, means that every project will have those.
To set to specific project:
```
git config user.name "username"
```

```
git config user.email "user@email.com"
```

- Initialize a local git directory
`git init # inside the directory you want...`

# 17.Git - Staging and Committing Changes

## Staging
Our Local Directory is considered the working area, then when we modify data in the project, we step up to the staging area.
Staging means telling git that these are the changes we made.
- To check what is exactly modified in our repo, use status sub command:
```
$ git status  
On branch master  
  
No commits yet  
  
Untracked files:  
 (use "git add <file>..." to include in what will be committed)  
       file1  
       file2  
  
nothing added to commit but untracked files present (use "git add" to track)
```

- To add the modified files to the staging are, use Add sub command:
```
git add file1 file2
```
- To see the tracked changes, use status sub command again:
```
$ git status  
On branch master  
  
No commits yet  
  
Changes to be committed:  
 (use "git rm --cached <file>..." to unstage)  
       new file:   file1  
       new file:   file2
```
- To remove a file from the staging are, use reset sub command:
```
git reset file2
```
- To add certain files based on file extension inside the directory:
```
git add "*.html" 
```
- To add sub directory:
```
git add src/
```
- To add certain files based on file extension in the sub directory:
```
git add "src/*.html"
```

> [!NOTE] 
> All the tricks above work with other sub commands like "reset", "commit"...etc
## Committing Changes 
Commits are a way of keeping track of changes, it is considered as save point, we can go back to if things didn't work out.
it is always recommended to add a comment to commits, for it will help you and the team working on the project.
```
git commit -m "comment here" 
```

### Types of Changes
#### Deleting a file

# Branches and Remote Repositories
Is a new and separate version of the main repo. it allows to work on different parts of the project without impacting the main branch.
- Create new branch
```
git branch test-new
```
- List branches
```
$ git branch  
* master  
 test-new
```
	 * means we are working on the master branch
- Change the working branch
```
$ git checkout test-new    
Switched to branch 'test-new'
```
