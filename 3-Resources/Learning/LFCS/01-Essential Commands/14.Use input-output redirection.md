# stdin, stdout, stderr
![[Linux-redirection-normal-flow.png]]
Unix-like Operating system provide at least three input/output channels, (or data streams), called stdin (standard input), stdout (standard output), and stderr (standard error). to allow communications between programs and the environment in which it runs in.
In Bash each has a number (0 to 2), it takes the name of [file descriptor](https://en.wikipedia.org/wiki/File_descriptor). it refers to a file, so it can be dealt with as any file.
## stdin (standard input) 0
Corresponds with what is typed in the terminal, and the two outputs.
## stdout (standard output) 1
For normal messages.
## stderr (standard error) 2
For Error Messages.
# Redirecting Output >/>>
stdout redirection, means altering the output of a command and what not, to another direction, ie files, other commands...etc
## (>) stdout Redirect and Overwrite
It overwrites the destination file.
- Example:
```
date > file1
cat file1    
Tue Jun 18 05:33:52 PM CET 2024
```
---
```
date > file1
cat file1
Tue Jun 18 05:35:06 PM CET 2024
```
## (>>) stdout Redirect and Append
It doesn't overwrite the file, it adds to it.
Example:
```
date >> file1    
issam@LFCS-Fedora-VM:~/lfcs-exercises/01/redirect$ date >> file1    
issam@LFCS-Fedora-VM:~/lfcs-exercises/01/redirect$ date >> file1    
issam@LFCS-Fedora-VM:~/lfcs-exercises/01/redirect$ date >> file1    
issam@LFCS-Fedora-VM:~/lfcs-exercises/01/redirect$ cat file1    
Tue Jun 18 05:35:06 PM CET 2024  
Tue Jun 18 05:36:13 PM CET 2024  
Tue Jun 18 05:36:16 PM CET 2024  
Tue Jun 18 05:36:16 PM CET 2024  
Tue Jun 18 05:36:17 PM CET 2024
```
