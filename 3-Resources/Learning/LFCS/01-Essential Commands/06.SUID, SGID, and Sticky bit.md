
| S-Permission | SUID | SGID | Sticky Bit |
| ------------ | ---- | ---- | ---------- |
| Value        | 4    | 2    | 1          |

# SUID
Set User Identification bit, it means that when a file is executed it executes as the User ID of the owner user, not the user executing it, it is represented with digit "4" in the first slot of permissions.
to set SUID permission to a file it goes like this:
```
chmod 4664 filename
-rwSrw-r-- # file's permission format.
```
# SGID
Set Group Identification bit, like SUID, it means the file will be executed as the group permissions, whomever executes it. it is represented with the digit "2".
- E.G:
```
chmod 2664 filename
-rw-rwSr-- # permission format of the file.
```
# Sticky Bit
This special permission affects only directories, it makes the content of a directory only deleteable by the owner and root. it is represented with the digit "1".
- E.G
```
chmod 1664 directory
drw-rw-r-T # The T shows that the sticky bit is enabled for the directory.
```

> [!faq] Capital S and lowercase s
> when setting the permission of user to 7, the "s" in permission format will appear as lowercase, but when set to 6 it will appear as capital "S", why ?
> **Answer: when capital "S" is the case, it means that the SUID is set but the file is not executable, lowercase "s", means SUID is set and the file is executable**
# Combination 
To combine both SUID and SGID, we need to sum the values up, 4+2=6, so 6 will set both SUID and SGID
