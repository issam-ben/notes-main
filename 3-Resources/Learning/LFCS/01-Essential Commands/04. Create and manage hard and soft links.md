# Inode
data structure, stores info about the file (metadata) except filename and the actual data, 

## What for ?
### How data is stored on disk ?
Data on disk is stored in the form of [memory pool](https://en.wikipedia.org/wiki/Memory_pool) or fixed-size blocks, which means that data are stored on disk in blocks, each block has a fixed size like 512 Bytes, here comes the benefit of the inode, so when data is being stored on disk, it stores it in block then the one next to it, if it doesn't find a free block next, it will find a free block in another area, in this case the inode stores in which blocks the file is in.

## info stored in inode
- file size
- Device on which the file is stored.
- User and group IDs associated with the file.
- Permissions needed to access the file.
- Creation, read, and write timestaps.
- Location of the data (though not the file path).
# Hard Links
A link in UNIX is a pointer to a file.
**Hard Link** is a link that not only points to a file, but to the inode, that means it is the same file but not duplicated.
- Examples:
Lets say we a have a .jpg file named *pic.jpg*, and we made a hard link of it in another directory named *pic-hln.jpg*, if we then delete the original file, *pic-hln.jpg* will still be accessible, so that means we can save up space, better than having multiple files.
- to create a hard link:
```
ln path/to/target/file path/to/link/file
```

Must Know:
- Each hard link is assigned to the same inode value as the original file.
- ls -l command shows all the links count.
- stat command shows links of a certain file
- removing files affects only the link count. deleting all links will delete the data.
- can't create hard link for a directory.
- can only hard link to the same filesystem. 
- must have proper permissions.
# Soft Links
Are like Shortcuts in windows. They point to the file itself not the data
- to create a soft link:
```
ln -s path/to/taget/file path/to/link/file
```

Must Know:
- soft link file start with an "L" in the ls command, in the permissions segmetn.
- readlink command shows the link of the file.
- soft link permissions doesn't matter, always the original file's permissions matter.
- if the original file location is changed, the soft link will break.
- you can soft link to directories, and other filesystems.
