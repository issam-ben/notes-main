## Network Segments 
A network segment is a smaller part of a larger network, separated by a device (hub, switch, router, bridge, repeater...etc).
## Bridging
Bridging is making two network segments function as a single network. it operates at the layer 2 (Data Link) of the OSI model.
Bridging in Linux simply is having two network interfaces each connected to a different network Segment, and combine them together. The bridge in Linux is often called ==The Controller== and the network devices that are part of the bridge are called ==ports==.
### Purpose: 
To connect different network segments and allow them to communicate as if they were on the same local network.
### Functionality: 
The Bridge functions by learning the MAC addresses of each device on each segment, it uses this information to forward packets only to the appropriate segment to reduce unnecessary traffic.
### Use Cases: 
- Extend networks: such as connecting a wired and wireless networks together.


## Bonding
Bonding is similar to bridging in the context of combining two network interfaces, but functions in another way, it combines two network interfaces to act as a single interface, meaning that bridging deals with many networks to make them one, bonding deals with many interfaces and one network.

### Purpose: 
* Increase bandwidth: combining two network interfaces with different speeds, can exploit the faster interface and boost the connection.
* Redundancy: Combining two network interfaces together will increase the the redundancy of the connection, so if a one interface fails, the other one is still working, the connection will not be lost.
### Bonding Modes
Linux can deal with bonding network interfaces in many ways, called bonding modes, there are 7 modes, numbered from 0 to 6.
#### Mode 0 (Round Robin): 
In this mode the packets are sent sequentially through each interface one by one, meaning if you have two interfaces the first packet will be sent through interface 1, and the second packet through interface 2, and 3rd packet through 1, and so on.
- it provides load balancing, and redundancy. 
#### Mode 1 (Active-Backup):
In this mode only one interface is used at a time, the other interfaces are put on standby, if the active interface fails, one of the standby interfaces will replace it.
- it provides redundancy.
#### Mode 2 (XOR - Exclusive Or):
Transmits packets based on hash policy, which can be altered via the _xmit_hash_policy option, the hash value is derived from the source and destination MAC addresses, in summary it makes sure that the connection from the same source and same destination goes through the same interface.
- it provides Load Balancing.
#### Mode 3 (Broadcast):
Everything is transmitted on all standby interfaces. Requires static EtherChannel to be enabled (not LACP negotiated). 
- it provides redundancy only.
#### Mode 4 (IEEE 802.3ad / 802.1ax - Dynamic Link Aggregation):
It allows multiple network links to be combined in one logical link, it requires a Switch that supports link aggregation protocols (802.1ad) (aka LAG/LACP).
- it provides Performance and Reliability.
#### Mode 5 (Adaptive Transmit Load Balancing):
Transmits data based on the interface load capability, if one interface is buy it will use another that is not.

> [!NOTE]
> - tlb_dynamic_lb = 1, then load is distributed according to the existing load carried by each standby interface.
> - tlb_dynamic_lb = 0, hash distribution is used to distribute the load, conversely if tlb_dynamic_lb=1 then the outgoing traffic is distributed according to the current load (computed relative to the speed) on each member interface.
> - xmit-hash-policy_ can be used to select the appropriate hashing for the setup

* it provides load balancing.
* it requires manual configuration.
#### Mode 6 (Adaptive Load Balancing):
It is similar to mode 5, except it doesn't require manual configuration, and load balancing is handled by Address Resolution Protocol -ARP.
- it provides load balancing.
