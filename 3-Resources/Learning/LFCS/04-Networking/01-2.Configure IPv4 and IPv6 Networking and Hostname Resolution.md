### Start a Network Interface
When the state of an interface is DOWN, we can bring it up using the command:
```bash
sudo ip link set dev wlp2s0f0u4 up
```
`set`: changes state, or type, or alias...etc of a device or group.
`dev`: specifies that the thing to set is a device.
`wlp2s0f0u4`: The name of the device.
`up`: The state to set it to.
### Manage IP Address Manually to a Network Interface
```
sudo ip addr add 10.0.0.40/24 dev enp6s0 # assings ip address
sudo ip addr delete 10.0.0.40/24 dev enp6s0 # remove ip address
```

### Set IP Address Automatically
Depends on the network configuration tool used by the Linux Distro:
* Ubuntu = `Netplan`.
* Fedora (Redhat)= `NetworkManger, Systemd-networkd`.
* Arch = `NM, Sysd-netd, iwd`.
* OpenSUSE = `Wicked`.
Most distros use NetworkManager, or Networkd.
#### Netplan
The default Ubuntu network configuration tool, it uses YAML format located in `/{lib,etc,run}/netplan/*.yaml
Directory priority is as follows:
```
1. /run/netplan
2. /etc/netplan
3. /lib/netplan
```
Netplan provides a network configuration abstraction over a backend ("renderer" in netplan terms), e.g Systemd-Networkd and NetworkManager, it handels both Physical and Virtual network interfaces via YAML, which in turn is translated to configurations compatible with the default backend. @IntroductionNetplan; @docileNetplanNetworkConfiguration2024.

To see the current netplan configurations:
`sudo netplan get`
```bash
network:  
 version: 2  
 ethernets:  
   enp1s0:  
     dhcp4: true
```
`dhcp4: true` means that the system will always ask for the configurations from a dhcp server, (e.g, Home wifi router has a dhcp server, that assigns IPs to devices on the network) '4' means ipv4. 
YAML files are sorted in [Lexicographical order](https://en.wikipedia.org/wiki/Lexicographic_order), meaning, 100 comes before 2.

##### Apply Configuration
To apply `netplan` configs, create a yaml config file, in the suitable directory, then run the command:
```bash
sudo netplan apply
```
###### Try Command
The `try` command is used to test configs, it gives a default 120 seconds of time before reverting to older settings, to see if it works well or not.
To set the timeout of `try` commands, use `--timeout` option like this:
```bash
sudo netplan try --timeout 30 # for 30 seconds.
```

> [!NOTE] Note
> if you have more than two configs present on the directory, `netplan` will apply the yaml files based on the file naming order. if you face any problem try to remove/backup other files, or comment them out.
