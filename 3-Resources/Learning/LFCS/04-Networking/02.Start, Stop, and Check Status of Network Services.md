Servers have many processes that deal with network data, to do so many purposes like sending a message, email, sharing a photo, browsing the web...etc. a prime example is ssh, which runs in the background and listens for incoming connections to let people login remotely.
To inspect what programs are running and listening for network connections we use two tools, `ss` which is the newer one, and `netstat`, is older but both use the same syntax.

## Inspect listening programs

```bash
sudo ss -ltunp  
Netid       State        Recv-Q       Send-Q                      Local Address:Port               Peer Address:Port       Process                                                                                   
udp         UNCONN       0            0                              127.0.0.54:53                      0.0.0.0:*           users:(("systemd-resolve",pid=682,fd=16))                                                
udp         UNCONN       0            0                           127.0.0.53%lo:53                      0.0.0.0:*           users:(("systemd-resolve",pid=682,fd=14))                                                
udp         UNCONN       0            0                  192.168.122.234%enp1s0:68                      0.0.0.0:*           users:(("systemd-network",pid=626,fd=22))                                                
tcp         LISTEN       0            511                               0.0.0.0:80                      0.0.0.0:*           users:(("nginx",pid=5534,fd=5),("nginx",pid=5533,fd=5),("nginx",pid=5532,fd=5))          
tcp         LISTEN       0            4096                           127.0.0.54:53                      0.0.0.0:*           users:(("systemd-resolve",pid=682,fd=17))                                                
tcp         LISTEN       0            4096                        127.0.0.53%lo:53                      0.0.0.0:*           users:(("systemd-resolve",pid=682,fd=15))                                                
tcp         LISTEN       0            200                             127.0.0.1:5432                    0.0.0.0:*           users:(("postgres",pid=4757,fd=6))                                                       
tcp         LISTEN       0            511                                  [::]:80                         [::]:*           users:(("nginx",pid=5534,fd=6),("nginx",pid=5533,fd=6),("nginx",pid=5532,fd=6))          
tcp         LISTEN       0            4096                                    *:22                            *:*           users:(("sshd",pid=1686,fd=3),("systemd",pid=1,fd=168))
```

Explaination:
- l= list only listening sockets.
- t= tcp connections.
- u= udp connections.
- n= numeric values, it shows the port number with service name.
- p= processes, requires privileges, it shows the process that is using the connection.
Adresses Explaination:
* ==127.0.0.1=== means the process is listening to connections from the localhost, meaning that the process will only connect with other processes running on the same computer, like `nginx` communicating with `postgresql`.
* ==0.0.0.0=== means the process is listening to connections from outside the localhost, be it on the internet or in the same `LAN`.
* <span>[::]</span> means the process is also accepting IPv6 connections.
