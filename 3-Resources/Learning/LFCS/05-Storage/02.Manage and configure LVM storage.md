# 02.Manage and configure LVM storage

## What is LVM
Created by Redhat in 2001, LVM (short for: Logical Volume Manager), is a mechanism in Linux for managing Storage, it works by combining Disks or Partitions (Physical Volumes) into Volume Groups (VGs), making them look like a single disk, and then can partition them to Logical Volumes (LVs).
LVM can make it very easy to manage storage, it allows to resize the LVs on the fly, by adding new Disks to a VG, or removing one.

## LVM Components 
### Physical Volumes
These are real Disks or Partitions, LVM consider them as PVs, they are the basic component to create an LVM storage on Linux.
Physical Volumes commands start with the letters pv, 
#### Managing Physical Volumes

##### Create Physical Volumes
To create a Physical Volume using a Disk or a partition, we use the command pvcreate followed by the path of the disk or partition as an argument:
```bash
sudo pvcreate /dev/vdd
```

##### Listing available Physical Volumes
Use these Commands:
```bash
sudo pvscan
sudo pvs
sudo pvdisplay
```

##### Change attributes of physical volume (pvchange)
The command ==pvchange==, is used to change attributes of a physical volume. it has 6 commands some with two switches:
- -a, --all: if no PV is selected in the command line, it uses all physical volumes are searched and used.
- --metadataignore (y|n): makes the PV ignores or un-ignore metadata areas on the PV. if ignored LVM will not store metadata.
- -u, --uuid: generate new random UUID for a specified Physical Volume.
- -x, --allocatable (y|n): enable or disable physical extents on a Physical Volume.
Examples:

```
sudo pvchange --metadataignore y /dev/vdd1 # makes PV vdd1 ignore metadata using the switch y, use n to disable it.
sudo pvchange -x y /dev/vdd1 # makes vdd1  allocatable
sudo pvchange -x n /dev/vdd1 # makes vdd1 not allocatable
```

##### Checking Physical Volumes Metadata
Use the command ==pvck==:
```bash
sudo pvck /dev/vdd # Perform comprehensive check on a PV.
sudo pvck metadata /dev/vdd # Check metadata of PVs for inconsistencies.
```
For more info use this [tutorial](https://www.linuxoperatingsystem.net/pvck-command-in-linux/). 

##### Move Data from PV to another PV
The command ==pvmove== is a command used to move Physical Extents of a Logical Volume (LV) from one PV to another within the same VG. some of the best cases it is used for are, replacing a failing disk, or reorganizing storage.

```bash
sudo pvmove /dev/vdd1 /dev/vdd2 # move all data from one PV (vdd1) to another (vdd2).
sudo pvmove /dev/vdd1 # move all data on vdd1 to any available PV in the same VG.
sudo pvmove /dev/vdd1:1000-2000 /dev/vdd2 # Moves extents from 1000 to 2000 to /dev/vdd2.
```

##### Remove Physical Volumes
in case of a need to remove a device from use by lvm, you can remove the LVM label with ==pvremove== command. it cannot be removed from a VG while it is used by an active LV.

```
sudo pvremove /dev/vdd1
sudo pvremove -ff /dev/vdd1
---other options:
pvremove -v / --verbose
pvremove --version
pvremove -t: test pvremove
```

##### Resize Physical Volumes
If you want to adjust the size of PV, you can use ==pvresize==.
sudo pvresize /dev/vdd1
- set the size of a PV
sudo pvresize --setphysicalvolumesize 40G /dev/vdd1
### Volume Groups (VG)
Volume Groups are the next level of abstraction in LVM, they are a collection of Physical Volumes as a storage pool, it combines the capacity of multiple raw storage devices (Physical Volumes).
#### Managing Volume Groups
##### Listing Volume Groups
To list available Volume Groups use these commands: 

```bash
sudo vgs         # a simple list of available VGs.
sudo vgscan      # scans for availabs VGs.
sudo vgdisplay   # detailed list of available VGs.
```
##### Create Volume Groups
Using the commang ==vgcreate==, the syntax is as follows:

```bash
sudo vgcreate <name-of-VG> <PVs-to-use>
sudo vgcreate VG-1 /dev/vda1 /dev/vdb
```
##### Extend Volume Groups
Extending a VG means adding more PVs to the VG, using ==vgextend== command.

```bash
sudo vgextend <volume_group> <physical_volume1> <physical_volume2>...
sudo vgextend VG-2 /dev/vdd2 /dev/vdd3
```
##### Reduce Volume Groups
As extending means, reducing VGs means removing one PV or more from a VG.

```bash
sudo vgreduce VG-2 /dev/vdd3
```
##### Remove Volume Groups
To remove a VG you can use the ==vgremove== command:

```bash
sudo vgremove <volume_group>
sudo remove VG-3
```

### Logical Volumes (LV)
LVs are partitions in LVM, they are the ones that gets formatted, and put data on.

#### Managing Logical Volumes
##### Create Logical Volumes
As other tools, ==lvcreate== is the tool to create logical volumes:

```bash
sudo lvcreate <-L size of LV> <-n name of LV> <VG_name>
sudo lvcreate -L 10G -n extra VG-2
```

##### Create Filesystems on Logical Volumes
the path to an LV in linux will be under /dev/VG-name, or in our case, /dev/VG-2, the file for the LV resides under VG-2, which in turn is a VG.

```bash
sudo mkfs.ext4 /dev/VG-2/extra
```

##### Mount a Logical Volume
Mounting a Logical Volume is like mounting any storage device, you use the ==mount== command, and using -t option specify the type of the filesystem, and specify the path the storage device, and then specify the path to which you want to mount your LV  to:

```bash
sudo mount -t <type> <LV_Path> <Mount_Path>
sudo mount -t ext4 /dev/VG-2/extra /mnt/extra
```
##### Resize Logical Volumes

```bash
sudo lvresize -L +2G VG-2/extra
```

After resizing the Logical Volume, the filesystem inside it should be resized too, depending on the filesystem there are different tools to resize each fs.
- EXT family: resize2fs: ==sudo resize2fs /dev/vdd1 12G== # desired size after resize.
- XFS: can only be expanded, using ==xfs_growfs /mount_point==
- btrfs: using command: ==btrfs filesystem resize 20G /mnt==

##### Remove Logical Volumes
Using the command ==lvremove==, it returns the previous used PEs to the VG.

```bash
sudo lvremove VG_name/LV_name
sudo lvremove VG-2/four
```

### Miscellaneous Operation on LVM
#### Show Free Space on a Volume Group

```shell
sudo vgs -S vgname=VG-2 -o vg_free
```
