Integrity is assuring that an organization's information is protected against unauthorized modifications, because Attackers that can intercept information can also try and change its content while its being transmitted.
For more info visit [ORM](https://www.openriskmanual.org/wiki/IT_Data_Integrity_Risk).

### Risks against Integrity
1- Unauthorized Modification of Information: this happens when an attacker gains access to a system and make modifications that violate a security policy, this can come from outside the company for ex attacks against banks where the attacker steals money, or from the inside like an employee raising their salaries
	-Protection: Least Privilege policy, by ensuring that every employee gets only the permissions they need

2- Impersonation: it is when an attacker pretends to be someone else (one who has access) to convince them to change data. it is related to [[social engineering]], and the best defense against it is strong user education.

3- Man in the Middle: it is an impersonation attack but on the electronic level, it is when an [[attacker]] sits between a user that wants to login into a [[system]], the attackers impersonates the system making the user think it connected to the real system, then the attacker forwards the packets between them.
for more info visit [Varonis](https://www.varonis.com/blog/man-in-the-middle-attack)

4- Replay Attack: the attacker captures login info and the replays it in the hope of gaining access.
	-Protection: both MITM and Replay attacks can be protected from by using encryption.
